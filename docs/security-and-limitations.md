# Security and limitations

## Trust and control

- Pool contracts have no owner, upgrade proxy, pause key, winner override, or privileged draw function.
- The keeper submits ordinary permissionless lifecycle transactions; it cannot select a winner.
- Proof-backed public decryptions are checked against the exact expected handle.
- The faucet is owner-managed test infrastructure and is not part of principal custody.
- The factory can create one pool for each registry-valid confidential token; it does not control deployed pools.

## Defensive design

- External token-moving functions are non-reentrant.
- Deposits are capped to the remaining encrypted total capacity.
- Withdrawal transfers at most the caller's encrypted principal.
- Claiming atomically clears winnings before transfer.
- Deposits close after a draw snapshot so current-draw odds cannot change.
- Batch sizes and participant counts are bounded.
- Encrypted values receive explicit contract/user ACL grants at every storage and transfer boundary.
- Zero-value Claim and Withdraw actions are stopped in the UI after a private balance check, producing an informational message instead of a wallet transaction prompt.

## Accepted prototype limitations

| Limitation | Consequence |
|---|---|
| Sepolia-only deployment | Test assets have no real value and availability depends on shared test infrastructure |
| Mock keeper-funded yield | The prize is not generated by a production lending strategy |
| 64 participants, 8 per batch | Demonstrates bounded confidential computation; not mainnet scale |
| Public aggregate eligible weight | Total pool participation value becomes readable during the draw |
| Public addresses and timing | FHE protects amounts, not transaction metadata or traffic analysis |
| Winner may self-reveal by claiming | A public claim transaction can correlate an address with a prize event even though the amount remains encrypted on-chain |
| Zero-value participation is possible | The prototype does not charge or enforce a minimum encrypted deposit |
| Non-upgradeable pools | Fixes require new deployments and migration, by design |

## Before production

A mainnet design needs an independent smart-contract audit, token/economic review, production yield-adapter risk controls, liveness objectives, funded monitoring, incident runbooks, privacy threat modeling, participant-scale benchmarking, and a carefully designed migration policy. Do not treat the Sepolia deployment as audited or production-ready.
